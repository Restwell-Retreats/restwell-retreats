# Comprehensive audit — 24 Aug 2026

Supersedes stale line-number citations in [TECH-DEBT-AUDIT.md](../TECH-DEBT-AUDIT.md) and [VISUAL-FRONTEND-AUDIT.md](../VISUAL-FRONTEND-AUDIT.md) (most of both documents' findings were already fixed before this pass — see "Already fixed, no longer valid" below). This is a live audit against the theme running on WordPress Playground (port 9402), verified via PHPCS, direct code review, and in-browser inspection (CDP + screenshots) across mobile/tablet/desktop.

## Method

- Activated the theme, ran Theme Setup, fixed test-environment config (site title, permalinks) that isn't a theme bug.
- Read `git status` to see what's mid-refactor (font/image asset cleanup — variable fonts replacing static weights, stock photography replacing placeholder bungalow shots).
- Grepped for the banned phrase, `[NEEDS:` placeholders, broken links/images, and checked every top-level page resolves via `restwell_nav_resolve_page_url()` (no hardcoded slugs).
- Walked the Accessibility, Pricing, and Home pages content in detail against the brief (practical confidence for wheelchair users/carers/funders): all three hold up — specific measurements (965mm/926mm door widths), an interactive door-width fit-checker with UK Approved Document M / BS 8300 references, honest limitations (shingle beach not wheelchair-friendly, narrow Harbour Street pavements), named hoist model + SWL, and a published rate card with real dated peak-season ranges. No invented facts found; nothing required a `[NEEDS:]` placeholder because the copy is already specific.
- Checked PHPCS security sniffs, largest functions (technical debt), JS structure, and CSS spacing-governance compliance.
- Screenshot/CDP sweep of Home and Pricing at mobile (390px) and desktop widths; checked hamburger tap-target size; checked for JS console errors and unloaded images.

## Investigated, not a bug

- A `Fatal error: restwell_migrate_seo_kp_titles_v12 not found` line in an old debug log — the function exists, is registered, and migrations are gated by a schema-version check; no matching entry in any current-session log. Stale entry from earlier development, not reproducible.
- Two images (`partners/continuity-of-care-services-long.png`, `partners/cqc-rating-good.jpg`) flagged by a naive `naturalWidth === 0` JS probe — both `loading="lazy"` and simply hadn't entered the viewport yet when probed; both return HTTP 200 and render correctly on scroll.
- Guessed page slugs (`funding-support/`, `website-accessibility/`) 404'd — wrong guesses on my part, not broken links. Real slugs (`resources/`, `accessibility-policy/`) resolve fine, and every in-theme link goes through `restwell_nav_resolve_page_url()` rather than a hardcoded path.

## Deliberately not changed

- `template-care.php` quotes a real, attributed guest testimonial ("G.G., Support team lead · Google review") containing the phrase "fully accessible." The copy-voice rule bans this phrase in Restwell's own writing; this is someone else's verbatim words in a cited blockquote, not a claim the site is making. Editing a real testimonial to fit house style would misrepresent what the reviewer said, which is a worse problem than the phrase itself. Left untouched; flagging here so it's a documented decision, not an oversight.

## Remaining technical debt (lower priority, not touched this session)

- `inc/crm/enquiries.php`: two functions (`restwell_crm_enquiry_detail`, `restwell_crm_enquiries_page`) at ~487–495 lines each, mixing query/business logic and HTML rendering. Admin-only surface, not guest-facing; refactor would need dedicated regression testing of the CRM screens rather than a quick pass.
- `assets/js/main.js`: single 2,200-line IIFE with ~95 named functions (not one god function, but one god *file*). Splitting into per-concern modules (nav/gallery/forms/faq) would need conditional per-template enqueues and full interaction regression testing across every page — left as-is to avoid introducing regressions without a test harness.
